## 1. 프로젝트 개요

### 1.1 개발 배경

사용자가 소중한 사진을 직접 색칠할 수 있는 컬러링북으로 변환하고자 하는 수요는 꾸준히 존재한다. 시중에서 판매되는 컬러링북은 전문 일러스트레이터가 수작업으로 도안을 제작하므로, 개인 사진이나 특정 이미지를 컬러링북으로 만들기가 어렵다. 이 프로젝트는 OpenCV 기반 이미지 처리 알고리즘을 통해 임의의 입력 이미지를 **Paint-by-Number 형식의 컬러링북**으로 자동 변환하는 시스템을 구현한다.

### 1.2 프로젝트 목표

| 목표 | 설명 |
|------|------|
| 색상 단순화 | 원본 이미지를 K개의 대표 색상으로 압축 |
| 닫힌 경계 생성 | 사용자가 색칠할 수 있는 폐영역 확보 |
| 영역 번호화 | 각 영역에 팔레트 번호를 자동 배정 |
| 난이도 분기 | 쉬움·보통·어려움 세 난이도 결과 자동 생성 |
| 웹 서비스 통합 | 프론트엔드를 통해 누구나 쉽게 사용할 수 있도록 배포 |

## 2. 시스템 파이프라인

전체 처리 흐름은 16단계로 구성된다. 입력 이미지 한 장에 대해 프로파일링부터 최종 렌더링까지 자동으로 수행된다.

```
입력 이미지
  │
  ├─ 1.  입력 이미지 프로파일링
  ├─ 2.  자동 처리 정책 선택
  ├─ 3.  작업 해상도 로드
  ├─ 4.  K-Means 전 색상/질감 단순화 (Mean Shift + Bilateral Filter)
  ├─ 5.  이미지별 최소 K 추정
  ├─ 6.  난이도별 K 결정
  ├─ 7.  배경 라벨 병합
  ├─ 8.  작은 라벨 섬 제거
  ├─ 9.  주요 색상 경계선 생성 (Object-first Edge)
  ├─ 10. 원본 디테일 경계 승격
  ├─ 11. 어두운 디테일 및 닫힌 세부 형태 보존
  ├─ 12. 경계선 연결 및 영역 분리 (Connected Components)
  ├─ 13. 색상 번호 배정
  ├─ 14. 최종 컬러링북 렌더링
  ├─ 15. 검수용 채움 Preview 생성
  └─ 16. 배치 오케스트레이션 및 CSV 요약
```

### 2.1 이미지 프로파일링 및 정책 선택 (단계 1–3)

`analyze_image_profile()`은 긴 변 최대 900px 샘플 이미지에서 복잡도를 빠르게 측정한다.

| 지표 | 측정 방법 | 역할 |
|------|-----------|------|
| `edge_density` | Canny 기반 | 세밀한 경계가 많은지 판단 |
| `blur_variance` | Laplacian 기반 | 이미지가 흐릿한지 판단 |
| `lab_spread` | Lab 색공간 분산 | 색상 다양성 측정 |
| `coarse_lab_colors` | 거친 Lab 색상 수 | flat-color 여부 판단 |

프로파일링 결과를 바탕으로 `choose_processing_policy()`가 4가지 정책 중 하나를 선택한다.

| 정책 | 조건 | 작업 해상도 | K 상한 |
|------|------|-------------|--------|
| `high` | edge density 높음 | 최대 2400px | 기본값 |
| `normal` | 일반 이미지 | 1800px 수준 | 기본값 |
| `soft` | blur variance 낮음 (흐릿) | 1800px 수준 | 기본값 |
| `simple` | flat-color 그림 | 1800px 수준 | 18 |

### 2.2 색상 단순화 (단계 4–8)

**K-Means 전 스무딩**은 JPEG 노이즈와 질감이 별도 색상 라벨로 분리되는 것을 막는다.

```
원본 이미지
  → pyrMeanShiftFiltering (sp=12, sr=28)
  → bilateralFilter (d=9, σ_color=90, σ_space=90)
  → K-Means
```

- Mean Shift: 유사한 색·위치의 픽셀을 묶어 큰 색 면으로 평탄화
- Bilateral Filter: 주요 경계는 보존하면서 미세한 색 변화만 제거

**최소 K 자동 추정**은 고정 K 대신 이미지별 최적 팔레트 크기를 도출한다.

```python
color_group_score = log2(coarse_unique_colors)
estimated = ceil(0.9 * color_group_score + lab_spread / 14.0)
min_k = clip(estimated, 3, 40)
```

**난이도별 K 결정**

| 난이도 | 기본 정책 | flat-color 정책 |
|--------|-----------|-----------------|
| 쉬움   | min_k + 0  | min_k + 0  |
| 보통   | min_k + 10 | min_k + 4  |
| 어려움 | min_k + 20 | min_k + 8  |

### 2.3 경계선 생성 (단계 9–12)

초기 방식(Edge-first)에서 **Object-first 방식**으로 전환한 것이 핵심 설계 결정이다.

```
[기존] Canny Edge → Connected Components
[현재] K-Means Label Map → 색 객체 Contour → Connected Components
```

| 경계선 유형 | 역할 | 렌더링 색상 |
|-------------|------|-------------|
| Segmentation Line | 색칠 영역을 나누는 닫힌 경계 | 검은색 |
| Detail Line | 표정·질감 표현용 보조선 | 회색 |
| Dark Detail | 눈동자, 작은 어두운 영역 | 회색 |

> **핵심 원칙:** Detail Line은 Segmentation에 사용하지 않는다. 두 역할이 섞이면 영역 과분할이 발생한다.

### 2.4 번호화 및 렌더링 (단계 13–16)

`assign_region_color_numbers()`는 각 Connected Component 안에서 최빈 K-Means 팔레트 라벨을 대표 색상 번호로 배정한다. 서로 떨어진 영역도 같은 대표 색이면 동일 번호를 갖는다.

번호 위치는 영역 내부에서 경계선과 가장 멀리 떨어진 지점(Distance Transform 최댓값)을 우선 사용하며, 번호끼리 겹칠 경우 일부를 생략한다.

## 3. 구현 과정 및 트러블슈팅

프로젝트 전반에 걸쳐 16개의 주요 기술적 문제를 식별하고 해결하였다.

### 3.1 Edge 끊김으로 인한 영역 분리 실패

**문제:** Canny + Color Boundary 방식에서 선이 끊기면 Connected Components가 영역을 제대로 분리하지 못했다. K=10 기준으로 segmentation 영역이 약 8개밖에 생성되지 않았다.

**원인 분석:** Edge Detection 우선 방식은 픽셀 단위 밝기·색 변화에 의존하므로, 그림자나 그라데이션이 있는 영역에서 경계가 자주 끊겼다.

**해결:** Edge-first 구조에서 **Object-first 구조**로 전환하였다. K-Means label map에서 같은 라벨을 가진 픽셀 집합을 색 객체로 보고, 각 객체의 contour를 경계선으로 사용함으로써 닫힌 영역 생성 안정성을 확보하였다.

---

### 3.2 Morphology 적용에 따른 선 두께 증가 문제

**문제:** closing 반복을 늘리면 영역 수는 증가하지만 선이 두꺼워져 컬러링북 품질이 저하되었다.

```
close_iter=1 → 영역 8개
close_iter=2 → 영역 56개 (하지만 선 두께 증가)
```

**해결:** Morphology closing 의존도를 낮추고, Anti-aliasing(`LINE_AA` → `LINE_8`)과 thinning을 적용하여 선을 얇게 만들었다. 단, 선이 얇아지면 segmentation이 불안정해지므로 **segmentation용 선과 표시용 선을 분리**하였다.

---

### 3.3 K 값 변화에 따른 영역 수 및 과분할 문제

**문제:** K를 고정값(K=30)으로 사용하면 단순한 이미지에서는 불필요하게 복잡해지고, 색 변화가 많은 이미지에서는 K가 부족했다.

**해결:** 이미지별 최소 K를 자동 추정(`estimate_min_k_from_smoothed_colors()`)하고, 이를 기준으로 난이도별 margin을 더하는 방식으로 전환하였다.

```
landscape 예시
  스무딩 색상 그룹 수: 949개
  추정 min_k: 13
  easy=13 / normal=23 / hard=33
```

---

### 3.4 그림자·그라데이션으로 인한 잘못된 영역 생성

**문제:** 사진 이미지에는 그림자와 그라데이션이 많아 K-Means가 미세한 명도 차이까지 별도 라벨로 분리하였다.

**해결:** K-Means 적용 전에 Mean Shift Filtering을 먼저 수행하여 색 면을 평탄화하였다. 이를 통해 그림자 영역이 독립된 색칠 영역으로 분리되는 현상을 완화하였다.

---

### 3.5 Bilateral Filter 및 Mean Shift 적용 과정

**문제:** Bilateral Filter만으로는 복잡한 그림자와 질감 노이즈를 충분히 제거하지 못했다.

**해결:** `pyrMeanShiftFiltering`(공간 반경 12, 색상 반경 28)을 먼저 적용하여 비슷한 색·위치의 픽셀을 하나의 색 면으로 묶은 뒤, Bilateral Filter로 경계를 보존하면서 미세한 노이즈만 추가로 제거하였다.

---

### 3.6 Hybrid Edge 방식의 한계

**문제:** Canny Edge + Color Boundary 조합에서 Color Edge Delta(`LAB ΔE > 35`)를 설정해도 그림자 경계가 여전히 살아남았고, edge detection 우선 구조 자체가 끊긴 선 문제를 해결하지 못했다.

**해결:** Hybrid Edge 방식을 보조적으로만 유지하고, 주 경계는 K-Means label contour에서 가져오는 Object-first 방식으로 대체하였다.

---

### 3.7 Edge-first에서 Object-first 방식으로 전환

**기존 방식:**
```
Canny / Hybrid Edge → Connected Components → Numbering
```

**전환 방식:**
```
K-Means Label Map → 색 객체 후보 → Contour 추출 → Segmentation Line 생성
```

Object-first 방식의 핵심은 "경계를 먼저 찾는 것이 아니라 객체를 먼저 찾는 것"이다. K-Means label map에서 라벨이 바뀌는 지점이 곧 색상 객체의 경계이므로, 이 경계는 원칙적으로 닫혀 있다.

---

### 3.8 Object-first 방식의 두꺼운 Contour 문제

**문제:** 여러 색 객체의 contour를 개별적으로 그리면 인접 영역의 공유 경계가 두 번 그려져 선이 두꺼워졌다.

**원인:**
```
영역 A의 contour + 영역 B의 contour
→ A–B 공유 경계가 2px 두께로 나타남
```

**해결:** region_map에서 인접 픽셀의 region id가 달라지는 지점만 경계로 사용하는 **공유 경계 기반 렌더링**으로 변경하였다.

```python
horizontal = region_map[:, 1:] != region_map[:, :-1]
vertical   = region_map[1:, :] != region_map[:-1, :]
```

---

### 3.9 Segmentation용 선과 표시용 선 분리

**문제:** thinning을 적용하면 시각 품질은 좋아지지만, 얇은 선은 Connected Components 입장에서 작은 틈만 있어도 영역이 연결되어 segmentation이 불안정해졌다.

**해결:** 두 역할을 완전히 분리하였다.

| 종류 | 역할 | 특징 |
|------|------|------|
| `segmentation_line_image` | 영역 분리용 내부 선화 | 닫힘 안정성 우선, 다소 두꺼움 |
| `object_line` (display) | 사용자 표시용 선화 | thinning 적용, 시각 품질 우선 |

---

### 3.10 Detail Edge와 Segmentation Edge 충돌 문제

**문제:** Canny 기반 detail edge를 segmentation에 함께 사용하면 작은 영역이 폭증하고 번호가 과다 생성되었다.

**해결:** Detail edge는 최종 렌더링 overlay에만 사용하고 segmentation에는 포함하지 않는 원칙을 수립하였다.

```
Segmentation Line → 영역 생성 및 번호 배치 기준
Detail Line       → 최종 표현용 overlay (segmentation 미적용)
```

---

### 3.11 번호가 Detail Line에 가려지는 문제

**문제:** 초기 합성 순서에서 `번호 라벨링 → detail edge overlay` 순서로 처리하면 detail 선이 번호 위를 덮어 가독성이 떨어졌다.

**해결:** 렌더링 순서를 변경하였다.

```
1. Object segmentation edge 그리기
2. Detail edge overlay (회색)
3. 색상 번호 라벨링  ← 항상 최상위 레이어
```

---

### 3.12 K 자동 추천 알고리즘 도입

**문제:** 고정 K는 이미지마다 과분할 또는 과단순화를 야기하였다.

**해결:** 스무딩된 이미지에서 coarse RGB 색상 그룹 수와 Lab spread를 조합하여 이미지별 최소 K를 자동 추정하는 알고리즘을 구현하였다.

```python
coarse_unique_colors = len(np.unique(pixels // 16, axis=0))
color_group_score    = log2(coarse_unique_colors)
estimated            = ceil(0.9 * color_group_score + lab_spread / 14.0)
min_k                = clip(estimated, 3, 40)
```

---

### 3.13 난이도별 K 자동 생성 기능 구현

**문제:** 동일 이미지에 대해 다른 복잡도의 결과를 제공하려면 K를 수동으로 여러 번 실행해야 했다.

**해결:** min_k를 기준으로 난이도별 margin을 자동 적용하는 `difficulty_k_values()` 함수를 구현하였다. 배치 파이프라인에서 이미지당 한 번의 프로파일링으로 세 난이도 결과를 모두 생성한다.

---

### 3.14 Region Contour 중복으로 인한 이중 경계 문제

**문제:** region별 contour를 각각 그리면 인접 영역의 공유 경계가 두 번 그려지는 이중 선 문제가 발생하였다. segmentation line을 빨간색으로 디버깅 표시하면서 명확히 확인되었다.

**해결:** `draw_simplified_boundary_layer()` 함수에서 region_map 기반 공유 경계 mask를 먼저 생성하고, `approxPolyDP`로 선을 단순화한 뒤 `cv2.polylines`로 한 번만 그리도록 변경하였다.

---

### 3.15 Shared Boundary 기반 렌더링으로 개선

region_map에서 인접 픽셀의 region id 차이를 기반으로 공유 경계만 추출하고, polyline 단순화(`epsilon_ratio=0.004`)를 통해 픽셀 단위 계단 현상도 완화하였다.

```python
def region_boundary_mask(region_map):
    boundary = np.zeros_like(region_map, dtype=np.uint8)
    boundary[:, 1:][region_map[:, 1:] != region_map[:, :-1]] = 255
    boundary[1:, :][region_map[1:, :] != region_map[:-1, :]] = 255
    return boundary
```

### 3.16 출력 해상도 확장 및 면적 기준 재설정

**문제:** 내부 처리 해상도가 낮으면 번호와 경계선이 뭉개져 보이고, 실제 프린트 결과물 품질이 떨어졌다.

**해결:** 원본 이미지를 크기 그대로 로드(`load_image_preserve_size()`)한 뒤, segmentation 전에 `SEGMENTATION_OUTPUT_SCALE = 2.0`으로 캔버스를 확대하였다. 면적 기반 파라미터도 `scale²`에 비례하여 재설정하였다.

```python
AREA_SCALE = SEGMENTATION_OUTPUT_SCALE ** 2
OBJECT_MIN_AREA_FOR_OUTPUT  = OBJECT_MIN_AREA  * AREA_SCALE
MIN_REGION_AREA_FOR_OUTPUT  = MIN_REGION_AREA  * AREA_SCALE
```

## 4. HCI 원칙별 분석

시스템 전체를 **효율성, 정확성, 의미성, 유연성, 일관성** 다섯 가지 HCI 원칙으로 분석한다.

---

### 4.1 효율성 (Efficiency)

> "사용자가 목표에 도달하기까지 소요되는 시간과 노력을 최소화한다."

#### 강점 — 자동화된 워크플로우

**직관적인 3단계 워크플로우**로 사용 장벽을 낮추었다.

```
사진 업로드 → 난이도 선택 → 변환
```

메인 화면 하단에 01–04 단계별 가이드를 배치하여 학습 곡선을 최소화하였다.

**드래그 앤 드롭** 지원(`PhotoInput` 컴포넌트)으로 파일 탐색기 호출 없이 빠르게 사진을 추가할 수 있다.

**반응형 상태 피드백**: `isGenerating` 상태를 통해 변환 버튼 텍스트를 '변환 중'으로 변경하고 버튼을 비활성화함으로써, 불필요한 중복 클릭을 방지하고 시스템 상태를 실시간으로 인지시킨다.

**알고리즘 수준의 효율성** — 배치 파이프라인에서 이미지를 한 번만 프로파일링하고 세 난이도 결과를 동시에 생성하므로, 동일 이미지에 대해 세 번 실행하는 방식보다 처리 시간이 크게 단축된다.

#### 약점 — 긴 대기 시간

연산 특성상 도안 생성에 **약 30초에서 1분 30초**가 소요된다. 적절한 피드백 없이 대기하면 시스템이 멈춘 것으로 오해할 소지가 있다.

#### 개선 제안

- **진행률 표시**: 단계별 로딩 메시지("색상 분석 중…", "경계선 생성 중…")나 프로그레스 바를 추가하여 심리적 대기 시간을 단축
- **자동 스크롤 알림**: 변환 완료 후 결과물 위치로 자동 스크롤하거나 Toast 알림으로 다음 행동을 유도

---

### 4.2 정확성 (Accuracy)

> "시스템이 오류를 방지하고, 결과물이 사용자의 의도를 정확히 반영한다."

#### 강점 — 오류 방지 및 결과 검증

**에러 핸들링**: 사진 업로드 전 변환 시도 시 `setErrorMessage`를 통해 "컬러링북으로 만들 사진을 먼저 선택해주세요."라는 명확한 안내를 출력한다.

**대기 중 조작 방지**: 생성 프로세스(`isGenerating`) 중에는 사진 업로드와 난이도 선택을 비활성화(`disabled`)하여 데이터 불일치 및 중복 요청 오류를 원천 차단한다.

**실시간 결과 비교**: `ImageComparison` 컴포넌트의 슬라이더를 통해 원본 사진과 생성된 도안을 픽셀 단위로 대조하여 결과물의 품질을 즉각 검증할 수 있다.

**검수용 Preview**: `segmentation_filled_preview` 이미지를 생성하여 영역 누수, 끊긴 경계, 너무 작은 영역을 시각적으로 확인한다.

**알고리즘 수준의 정확성** — `closed_detail_shape_edges()`와 `connect_segmentation_edges()`가 끊긴 경계를 연결하여 색칠 영역이 잘못 합쳐지는 오류를 줄인다.

#### 약점

작은 영역은 과분할과 누락이 모두 발생할 수 있어 Preview 검사 없이는 오류를 발견하기 어렵다.

#### 개선 제안

- 클라이언트 측 파일 형식 필터링(PDF, GIF 등 미지원 형식 사전 차단)
- 영역 수가 임계값을 초과하거나 미달할 때 사용자에게 경고 표시

---

### 4.3 의미성 (Meaningfulness)

> "시스템이 제공하는 정보와 시각 요소가 사용자에게 명확한 의미를 전달한다."

#### 강점 — 시각적 의미 전달

**메타포(Affordance) 활용**: 업로드 아이콘(Upload), 화살표(ChevronDown), 슬라이더 핸들(Code 아이콘) 등 익숙한 시각적 기호를 사용하여 설명 없이도 기능을 유추할 수 있다.

**결과 정보 제공**: "보통 난이도, 10색으로 생성되었습니다." 문구를 통해 도안 생성 기준과 결과를 명확히 매칭시킨다.

**알고리즘 수준의 의미성** — `source_detail_boundary_edges()`와 `dark_detail_region_edges()`가 K-Means만으로는 사라지기 쉬운 표정, 눈동자, 작은 물체 경계를 보존하여 원본 이미지의 구조를 이해할 수 있게 유지한다.

**팔레트 번호 의미**: 영역 고유 ID가 아닌 대표 색상 번호를 사용하므로, 서로 다른 위치에 있는 같은 색 영역에 동일 번호가 부여된다. 사용자는 "5번 = 하늘색"이라는 규칙을 이해하고 일관되게 적용할 수 있다.

#### 약점

난이도(쉬움/보통/어려움)가 실제 색상 수(K값)와 어떻게 매칭되는지 사용자가 직관적으로 알기 어렵다.

#### 개선 제안

- 단계별 로딩 메시지 다양화: "AI가 색상을 분석하고 있습니다…", "도안 경계를 생성 중입니다…" 등
- 난이도와 K값의 관계를 툴팁으로 제공 (예: "보통 = 약 23가지 색상")

---

### 4.4 유연성 (Flexibility)

> "다양한 사용자와 다양한 이미지 유형에 적응할 수 있도록 조절 가능한 옵션을 제공한다."

#### 강점 — 사용자 맞춤 옵션

**난이도 조절 시스템**: `DifficultyDropdown`을 통해 '쉬움', '보통', '어려움' 세 단계를 제공하여 사용자 숙련도에 맞는 도안 생성을 지원한다.

**다양한 저장 옵션**: 도안 이미지 다운로드 외에 '색상표 포함 결과 보기'를 지원하여 실제 채색 시 참고 자료로 활용할 수 있다.

**알고리즘 수준의 유연성** — 자동 처리 정책(`high/normal/soft/simple`)이 풍경, 캐릭터, 인물, flat-color 그림 등 다양한 이미지 유형에 자동으로 적응한다. `--max-size`와 `--no-auto-policy` 옵션으로 전문 사용자는 직접 파라미터를 제어할 수도 있다.

**지원 형식**: `.jpg`, `.jpeg`, `.png`, `.bmp`, `.webp`, `.tif`, `.tiff` 등 다양한 이미지 확장자를 지원한다.

#### 약점

프리셋 난이도 외에 색상 수를 직접 입력하는 커스텀 모드가 없다.

#### 개선 제안

- 고급 사용자를 위한 K값 직접 입력 '커스텀 모드' 도입
- 경계선 두께, 최소 영역 크기 등 파라미터 UI 제공

---

### 4.5 일관성 (Consistency)

> "모든 상태와 화면에서 동일한 규칙과 스타일이 유지되어 사용자가 결과를 예측할 수 있다."

#### 강점 — 디자인 및 알고리즘 통일성

**디자인 시스템**: Tailwind CSS 기반으로 여백(Gap, Padding), 색상 팔레트(Gray-900, Blue-600), 둥근 모서리(rounded-2xl) 등의 스타일을 전체 시스템에 일관되게 적용한다.

**타이포그래피**: Pretendard 가변 글꼴을 프로젝트 전체에 적용하여 심미적 통일성과 가독성을 확보한다.

**컴포넌트 재사용**: `Header`, `Footer`, `Button` 스타일이 모든 상태(입력 전, 로딩 중, 생성 후)에서 동일한 레이아웃 구조를 유지한다.

**알고리즘 수준의 일관성** — 검은 선은 색칠 영역 경계, 회색 선은 보조 정보라는 역할이 모든 출력에서 일관되게 유지된다. 번호와 팔레트는 같은 규칙으로 배치되어 사용자가 어떤 이미지에서든 결과를 동일한 방식으로 해석할 수 있다.

## 5. 결론 및 향후 개선 방향

### 5.1 결론

본 프로젝트는 OpenCV 기반 이미지 처리 알고리즘과 React 웹 프론트엔드를 결합하여, 임의의 입력 이미지를 Paint-by-Number 형식의 컬러링북으로 자동 변환하는 완성된 시스템을 구현하였다.

기술적으로는 Edge-first 방식의 한계를 파악하고 **Object-first Segmentation 구조**로 전환한 것이 핵심 성과다. Segmentation Line과 Detail Line의 역할 분리, 공유 경계 기반 렌더링, 이미지별 K 자동 추정을 통해 다양한 이미지 유형에서 안정적인 결과물을 생성할 수 있게 되었다.

HCI 관점에서는 효율성(자동화된 워크플로우), 정확성(에러 핸들링, 슬라이더 비교), 의미성(Affordance, 결과 문구), 유연성(난이도 조절), 일관성(디자인 시스템)의 다섯 원칙을 모두 고려하여 시스템을 설계하였다.
